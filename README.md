# Определение границ сельскохозяйственных полей по снимкам Sentinel-1 и Sentinel-2

Автоматическое выделение контуров полей на основе пиксельной классификации и
морфологической обработки спутниковых данных.

## Постановка задачи

Разработан прототип решения задачи дистанционного мониторинга
сельскохозяйственных территорий. На вход подаются совмещённые снимки Sentinel-1
(радар) и Sentinel-2 (оптика) одной территории; на выходе — векторный слой
полигонов полей с типом покрытия (`vegetation` / `bare_soil`).

## Метод (пайплайн)

Последовательная обработка в скрипте `extract_fields.py`:

1. **Пространственное разбиение** — 20 % тайлов (`tile_id`) целиком
   откладываются для оценки качества, остальные идут в обучение.
2. **Обучение Random Forest** — на 300 000 случайных пикселях train-тайлов по
   4 каналам (B02, B03, B04, B08). `n_estimators=40`, `max_depth=12`.
3. **Попиксельная классификация** — предсказание класса (`vegetation` /
   `bare_soil`) случайным лесом.
4. **Выделение границ** — фильтр Собеля по NIR-каналу (B08), порог —
   88-й перцентиль. Пиксели дорог/межей «стираются», разбивая смежные
   поля.
5. **Морфологическая очистка** — `remove_small_objects` (мин. 200 пикселей)
   и `remove_small_holes` (макс. 200 пикселей).
6. **Оценка качества** — IoU и F1 на отложенных тайлах до и после
   морфологии → `metrics_extract_fields.json` (см. раздел «Метрики качества»).
7. **Векторизация** — `rasterio.features.shapes` → GeoDataFrame →
   `field_boundaries.gpkg`.

## Запуск

Полный конвейер (обучение + классификация + векторизация):

```bash
python3 extract_fields.py
```

Для работы требуется 4–8 ГБ свободной оперативной памяти (Random Forest
читает 300 тыс. строк, полный снимок весит ≈300 МБ в float32 на канал).

На выходе создаются `field_boundaries.gpkg` и `metrics_extract_fields.json`.

Оценка любого готового результата (GeoJSON/GPKG с колонкой `land_cover`
или `class_id`) и тесты метрик:

```bash
python3 evaluate.py field_boundaries.gpkg              # тестовые тайлы
python3 evaluate.py field_boundaries.gpkg --subset all # все размеченные пиксели
pytest
```

При первом запуске разметка из `dataset.csv` собирается в растр и кэшируется
в `labels_cache.npz` (~1–2 минуты), дальше оценка занимает секунды.

## Просмотр результата

Откройте `field_boundaries.gpkg` в QGIS (или другом ГИС-приложении):

```bash
# QGIS (если установлен)
open field_boundaries.gpkg
```

Либо импортируйте через QGIS: **Layer → Add Layer → Add Vector Layer**.

Стиль: раскрасьте по атрибуту `land_cover`:
- `vegetation` → зелёный
- `bare_soil` → коричневый

Для подложки используйте `TRUE_COLOR.tif`.

## Метрики качества

Эталон — попиксельная разметка `class` из `dataset.csv` (координаты `x`/`y` —
пиксели растра). Для каждого класса:

- **IoU** = TP / (TP + FP + FN)
- **F1** = 2·TP / (2·TP + FP + FN) (совпадает с коэффициентом Dice)
- **precision** = TP / (TP + FP), **recall** = TP / (TP + FN)

Основные сводные метрики — **mIoU** и **macro-F1** (среднее по классам).
Классы несбалансированы, поэтому pixel accuracy завышает качество.
**Покрытие** — доля размеченных пикселей, попавших в какой-либо полигон.
Непокрытые пиксели считаются промахом (FN).

Оценка выполняется на отложенных тайлах, которые модель не видела при
обучении. Соседние пиксели почти одинаковы, поэтому случайное разбиение по
пикселям дало бы завышенные метрики.

Результаты на тестовых тайлах (1,88 млн пикселей):

| Этап | IoU bare_soil | IoU vegetation | **mIoU** | **macro-F1** | Pixel acc. | Покрытие |
|---|---|---|---|---|---|---|
| Базовый вариант: пороги NDVI (33/66 перцентили) | 0.516 | 0.624 | 0.570 | 0.725 | 0.693 | 86.6 % |
| Random Forest, попиксельно | 0.930 | 0.984 | **0.957** | **0.978** | 0.987 | 100 % |
| Random Forest + разрезание границ и морфология (итог) | 0.895 | 0.691 | 0.793 | 0.881 | 0.733 | 73.8 % |

- Random Forest почти точно воспроизводит классы покрова.
- Разрезание по границам Собеля удаляет ~26 % пикселей (дороги, межи,
  краевые зоны). Поэтому снижается recall и IoU `vegetation`, при этом
  precision остаётся ≈ 0.99: всё, что попало в полигоны, классифицировано верно.
- Пороги NDVI относят к почве треть снимка, хотя почвы ~18 %:
  recall `bare_soil` равен 1.0, а precision — 0.52.

> **Ограничение эталона.** Разметка `class` полностью совпадает с каналом SCL
> (Scene Classification) Sentinel-2: `vegetation` = SCL 4, `bare_soil` = SCL 5.
> Это проверено на всех 9,4 млн строк. Метрики показывают согласие с
> автоматической классификацией ESA, а не с ручной разметкой границ полей.
> Для оценки самих контуров нужна эталонная разметка полей (например,
> AI4Boundaries или Fields of The World).

## Результаты

- Выделено **1094 поля**: 886 с растительностью, 208 с открытой почвой.
- Качество классификации (тестовые тайлы): mIoU = 0.793, macro-F1 = 0.881
  для итоговой маски полей.
- Визуальное качество: большинство контуров повторяют реальные границы,
  дороги и лесополосы использованы как естественные разделители.
- Ограничения: возможны случаи слияния смежных полигонов со схожим
  спектром, требуется настройка порогов морфологии.
